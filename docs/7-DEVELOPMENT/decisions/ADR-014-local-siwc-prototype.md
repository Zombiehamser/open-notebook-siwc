# ADR-014: Локальная авторизация SIWC в отдельном провайдере

- **Статус**: Неофициальный текстовый провайдер; владелец принимает условия своего аккаунта.
- **Область**: Локальная однопользовательская установка в Docker.

## Решение

Добавить провайдер `chatgpt_siwc` через существующий ModelManager. Он реализует
контракты Esperanto и LangChain, использует официальный OAuth public-client flow
и публичный Responses API. Для первоначального входа использовать отдельную CLI
с временным loopback callback. Это позволяет проверить полный протокол до
разработки дополнительного UI авторизации.

Динамический client ID относится к проверенному аккаунту, host ID сохраняется
для установки. Сессии хранятся в отдельном локальном каталоге с ограниченными
правами. База Open Notebook содержит только связь credential → client ID.
Обновление токенов блокируется между процессами; новые запросы после выхода
не используют очищенную сессию. Прямой сетевой fallback отсутствует.

```text
Владелец → официальный вход → отдельное локальное хранилище
                                      ↓
Open Notebook → ModelManager → провайдер SIWC → Responses API
```

## Границы

Прототип принимает извлечённый текст. Успех требует непустого ответа и события
`response.completed`. Поля генерации, которые SIWC не поддерживает, в запрос не
передаются. Лимит подписки не вызывает смену аккаунта, платного провайдера или
автоматическое повторение того же фонового запроса.

Фоновые запросы требуют отдельного флага согласия при входе. Штатный worker
помечает свою роль через окружение. Другие способы запуска worker обязаны
сохранять эту настройку. Прототип не предназначен для обслуживания чужих
запросов одной подпиской.

Подкасты используют отдельный путь через podcast-creator. До подключения этого
контракта SIWC-модели там отклоняются с явной ошибкой. Embedding и TTS остаются
самостоятельными провайдерами. OAuth-токены, данные и конфигурация конкретного
пользователя не входят в исходники, образы и CI.

## Альтернативы и сопровождение

Универсальный OpenAI-compatible шлюз не выбран: он расширяет область доступа
к подписке и усложняет привязку запросов к подключённому приложению. Импорт
авторизации Codex и ChatGPT cookies не используется. Код SIWC Devkit не копируется.

Доработка отделена от upstream. Обычный test workflow включает тесты нового
провайдера. Отдельный ручной workflow пробует merge стабильного upstream-тега
в временной CI-копии и проверяет backend/frontend. Он не обновляет рабочую
установку и не получает личную авторизацию.

Сохраняются MIT и уведомление автора Open Notebook. Для доступа к сервису
продолжают действовать условия SIWC и ограничения аккаунта.
